# 0004 记录可审计的验证矩阵

**Type:** AFK  
**Status:** Ready

## What to build

在候选实现完成后，为每条验收条件记录 `verified`、`failed` 或带原因的 `not-run`，并关联宿主验证命令或预览运行时产生的证据。实现结果与验证基础设施结果必须分开：代码检查失败可以阻止候选实现完成；网络、代理、端口或浏览器权限导致无法验证时，应保留候选实现并明确显示环境阻塞。

工作台需要用验证矩阵驱动后续阶段和产品界面，避免把“Codex turn 成功但构建/页面未验证”显示成完整完成，也避免把环境故障误报成执行票实现失败。

## Acceptance criteria

- [ ] 每条验收条件都有稳定标识、结果状态、证据摘要和记录时间。
- [ ] 类型检查、构建、健康检查和目标页面预览可以分别贡献验证证据。
- [ ] `failed` 与 `not-run` 的判定规则明确；网络受限、代理不可达、禁止监听和浏览器权限拒绝归入可识别的环境原因。
- [ ] Codex turn 成功但必要验证未运行时，需求停留在验证阶段，不进入待产品验收。
- [ ] 环境阻塞不会把已完成的执行票重新标记为代码实现失败。
- [ ] 页面同时展示候选实现状态和验证矩阵，并允许在环境恢复后只重跑验证。
- [ ] 端到端测试覆盖全量通过、代码检查失败和环境导致 `not-run` 三条路径。
