# 0002 在工作台宿主执行声明式验证命令

**Type:** AFK
**Status:** Done

## What to build

让目标项目配置声明类型检查、构建等验证命令，并由工作台宿主进程在目标项目根目录执行。执行 Agent 负责形成候选实现，不再依赖受限 Codex 沙箱完成需要宿主代理、网络或较长运行时间的生产构建。

每条验证命令需要明确的环境策略、超时、取消和输出上限。工作台不得盲目继承会改变构建语义的异常环境值；代理变量应按宿主可访问性处理，同时保留目标项目显式声明的构建模式。命令失败时保存首个有效错误，而不是只记录递归脚本的汇总退出码。

该切片应覆盖已观察到的两类构建问题：非标准 `NODE_ENV` 导致 Next.js 构建行为不一致，以及沙箱无法访问宿主 `127.0.0.1:7897` 代理、造成 `next/font` 下载失败。

## Acceptance criteria

- [x] 目标项目配置可以声明按顺序执行的验证命令及单项超时。
- [x] 工作台宿主执行验证命令，并记录命令、开始/结束时间、退出码和经过脱敏的末尾输出。
- [x] 验证进程不会继承非标准 `NODE_ENV`；需要 production 的命令以确定值运行。
- [x] 超时会终止工作台拥有的整个进程组，并被记录为 timeout，而不是模糊的退出码 130。
- [x] 构建日志保留首个可操作错误，例如预渲染异常或字体获取失败。
- [x] fixture 测试覆盖成功、非零退出、异常环境和超时四种结果。
