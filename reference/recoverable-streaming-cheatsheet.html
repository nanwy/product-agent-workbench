可恢复流式对话

一句话：当前是“结构化事件流”，不是“token 文字流”；服务端完整快照是真值，SSE 只催浏览器取新快照。

当前真实协议

codex exec --experimental-json 中，assistant 正文通常由 item.completed 一次给全；item.updated 不等于文字 delta。

安全 delta

仅当 incoming.startsWith(current + pending) 时截取尾部；否则直接采用完整快照。

恢复原则

SSE 可以丢，Requirement 快照不能丢。通知到达或轮询触发后都重新读取真值。

五段链路

Codex SDK结构化 item 事件
Adapter类型 + 稳定 ID
Requirement完整持久快照
SSE / 轮询通知重新读取
Zustanddelta + 合帧投影

面试官追问

SDK 现在逐字吗？

不逐字。当前 exec 的 assistant 正文通常完成后一次到达；逐 token 需要 app-server 的 delta 事件。

为什么不只传 delta？

浏览器断线漏掉中间片段后，后续 delta 无法补全；完整快照可以立即恢复。

为什么还要前缀校验？

上游可能修订之前的文本。不是前缀时硬切 delta 会产生错误内容，必须回退到快照。

为什么用 rAF？

数据到达频率可能高于屏幕绘制频率。每帧提交一次，减少当前消息的状态更新；不是只渲染尾部字符。

为什么稳定 ID？

同一消息或工具从 running 到 completed 应更新原项；按 ID 订阅也让历史消息不受当前回复波及。

为什么等 turn completed？

文本里看到 READY 不代表本轮已经稳定结束；双条件防止半截协议提前打开业务门禁。
