app-server → SSE → React Query

快路负责立即显示：delta → 50ms/4KB 批次 → Query Cache。稳路负责恢复：累计全文 → 500ms/32KB 持久化 → 完整快照。item.completed 最后校准。

九步链路

  1. 服务端创建 streaming assistant 占位消息。
  2. 每 Turn 启动一个 codex app-server 子进程。
  3. Adapter 将 item/agentMessage/delta 分到 onTextDelta。
  4. 同 item delta 累计成全文，同时分配 Turn 连续序号。
  5. 50ms 或 4KB 后合成 AgentStreamBatch。
  6. SSE 把 batch 投影进 React Query。
  7. 500ms 或 32KB 后，累计全文写入 Requirement。
  8. 非正文或终态前 flush 所有缓冲。
  9. item.completed 全文按同 item ID 替换，invalidate 后重取快照。

浏览器判断

条件动作原因
end <= last忽略重复批次
start === last + 1不可变追加连续批次
start > last + 1invalidate 快照中间缺包，停止猜测
incoming revision < current拒绝迟到 HTTP 不能让页面倒退

SSE 健康

batch 实时投影；30 秒低频快照校准。

SSE 断线

切换为 3 秒轮询。EventSource 重连不等于事件补放。

先 refetch 权威快照，再恢复实时投影。

一句话回答常见追问

为什么不是 WebSocket？ 当前只需要服务端单向推送，用户命令继续走 mutation；正确性来自快照，不来自双向连接。

为什么保留 Zustand？ 可用于纯客户端状态，但服务端 Requirement 只放 React Query，避免双数据源。

是不是逐字？ 是真实文字 delta，不保证逐字。实际粒度由 app-server 和模型决定。

最终成果？ 正文渐进出现；重复不重放、缺包能恢复、刷新有内容、终态全文可校准。
