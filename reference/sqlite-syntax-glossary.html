Migration 中会遇到的全部关键词

CREATE TABLE name
创建名为 name 的表；后面的括号列出字段和约束。
TEXT
文本，例如 ID、标题、状态。
INTEGER
整数，例如 attempt、revision、Unix 时间。
BLOB
原始字节，不替你解释内容；对应 Go 的 []byte。
NOT NULL
必须提供值。没有写 NOT NULL 的普通字段默认允许 NULL。
PRIMARY KEY
表的主要身份，必须唯一；一张表只能有一个主键。
UNIQUE
值或一组值不能重复；一张表可以有多个 UNIQUE。
CHECK (条件)
INSERT 或 UPDATE 时条件必须成立，例如 attempt >= 1。
IN ('a', 'b')
值只能从列表中选择，常用于状态枚举。
REFERENCES parent(id)
当前值必须能在父表 parent 的 id 中找到。
ON DELETE RESTRICT
还有子记录引用父记录时，拒绝删除父记录。
CREATE INDEX name
为查询建立额外查找结构；name 是索引自己的名字。
ON table(a, b)
索引建立在哪张表、按哪些列排列；顺序很重要。
CREATE UNIQUE INDEX
既加速查询，也拒绝索引列上的重复值。
WHERE 条件
只让符合条件的行进入索引；这叫部分索引。
AUTOINCREMENT
SQLite 特有；只用于 INTEGER PRIMARY KEY，保证自动 ID 不复用历史值，不保证连续。

表级约束怎么读

UNIQUE (order_id, item_id, attempt)

不是说三列分别不能重复，而是说“三个值组成的组合”不能重复。两个不同 attempt 可以拥有相同 order_id 和 item_id。

CHECK (status IN ('waiting', 'running', 'done'))

先读里面：status 必须属于括号中的三个字符串。再读外面：每次写入都检查这件事。

索引语句怎么读

CREATE INDEX idx_runs_queue
ON runs(status, queue_seq);

创建一个叫 idx_runs_queue 的索引；它属于 runs 表，先按 status 分组，再按 queue_seq 排列。它服务“找某个状态下最早序号”这种查询。

CREATE UNIQUE INDEX ux_one_active
ON runs(owner_id)
WHERE status IN ('waiting', 'running');

只把 waiting/running 行放进唯一索引。因此同一个 owner 只能有一个活动 run，但 done/failed 历史可以保留多条。

阅读顺序

  1. 先圈字段名

    不要先看约束，先确认这一行保存什么。

  2. 再看类型

    TEXT、INTEGER 还是 BLOB。

  3. 最后问约束防什么错

    不能缺失、不能重复、不能越界，还是必须有父记录。

  4. 表写完再读索引

    每个索引必须能对应一条真实查询或业务不变量。
