# 已建立快照优先的恢复模型

用户已经能说明轮询用于让页面最终收敛到服务端状态，也能在新旧文本不满足前缀关系时选择放弃 delta、采用完整快照。用户也能判断前缀比较必须包含尚未 flush 的 pending delta；下一步需要准确推演忽略 pending 的后果是重复追加，而不是丢失内容。性能层仍需区分：delta 与 `requestAnimationFrame` 减少当前消息的状态提交，规范化 Store 和按 ID 订阅负责隔离历史消息，实现并不是只渲染尾部字符。

## Evidence

用户正确推演了断线兜底和非前缀修订，并正确选择用“已显示正文 + pending delta”参与下一次前缀比较；但把选错后的结果判断成丢失内容，尚未完整掌握缓冲区合并过程。
