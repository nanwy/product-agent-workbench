Lesson 0005 · 浏览器实现

页面可以猜，不能死扛

SSE 到达时，浏览器先把 delta 投影进 React Query，让用户马上看到。只要序号或 revision 说不清，它就停止拼接，回服务端拿完整快照。

为什么服务端状态统一放 React Query

以前页面同时有服务端快照和 Zustand 会话副本。一次 mutation、一次 SSE 刷新和一次轮询可能分别更新不同 Store，很难回答“现在谁是最新的”。当前实现把 HTTP、SSE、轮询和按钮 mutation 都收口到同一个 Query Cache。

Zustand 没有被禁用，依赖也保留着。以后弹窗开关、筛选条件、未提交草稿这类纯客户端状态仍然适合放 Zustand。服务端 Requirement 不再复制进去。

Query Cache 里有两种视图

WorkbenchSnapshot

["workbench", "snapshot"]

完整服务端快照，包含当前 Requirement、历史记录、目标项目运行状态和执行事件。

ConversationProjection

["workbench", "conversation", requirementId]

为渲染整理出的 messageIds + messagesById，另外保存每个 Turn 的最后序号和 revision。

单独的 conversation query 不是第二份真值。它是可重建的读模型：任何时候都能用 WorkbenchSnapshot 重新生成。

一个 SSE batch 到达后怎么处理

src/store/workbench-query.ts · applyAgentStreamBatch()

last = lastSequenceByTurn[turnId] ?? 0

if batch.sequenceEnd <= last:
  return true              // 重复批次，已经处理过

if batch.sequenceStart > last + 1:
  return false             // 中间有缺口，不能继续猜

找到 target message 和 item segment
不可变地追加 batch.delta
记录新的 lastSequence 和 revision

发现缺口时不能只追加 batch 4–5。你不知道 seq 3 是一个字、一段工具说明，还是改变业务门禁的内容。停止猜测反而是最便宜的正确方案。

revision 防什么

假设浏览器已经通过 SSE 显示 revision 10 的内容，同时一个更早发出的 HTTP 请求慢慢返回 revision 8。如果直接接收，页面会倒退。

当前投影：revision 10，正文="建议只修改登录页"
迟到快照：revision 8， 正文="建议"

projectConversation():
  previous.revision > requirement.updatedAt
  → 保留 previous

applyWorkbenchSnapshot() 对完整 Requirement 也做同类判断。这样 mutation 返回值、轮询结果和 SSE 投影可以共享一个 Cache，而不是互相覆盖。

EventSource 连接状态怎么影响轮询

src/routes/index.tsx · WorkbenchPage()

状态动作轮询间隔
首次进入loader 提供 SSR 快照，浏览器建立 EventSource连接确认前按断线策略
SSE onopen先 refetch 权威快照，再标记 connected30 秒低频校准
stream-batch直接投影；缺序号才 invalidate不额外轮询
invalidate将 snapshot 标旧并后台重取保持当前策略
SSE onerror标记 disconnected3 秒降级轮询
重新连接先校准断线期间状态，再恢复实时投影回到 30 秒

SSE 心跳只能帮助连接保持活跃，不能补回漏掉的业务事件。真正的恢复动作是 refetch 快照。

为什么历史消息不会全跟着重画

src/components/workbench-panels.tsx · ConversationTimeline / ConversationMessageRow

  1. 时间线只取 messageIds。
  2. 每个 MessageRow 用 select 只取 messagesById[id]。
  3. 流式 batch 只复制目标 message、segments 和对应 text segment。
  4. 其他消息继续复用旧对象引用，selector 结果没变。

这里减少的是受影响的 React 组件，不是让 DOM 只渲染新来的几个字。当前消息仍然拿完整累计正文渲染。

最终全文如何覆盖临时拼接

delta 使用的 item ID 和 item.completed 的 item ID 相同。完成事件落盘时，applyPlanningEvent() 找到同 ID text segment，直接替换。随后 invalidate 触发快照同步。

临时投影：item-7 = "建议只修改登陆页"
完成全文：item-7 = "建议只修改登录页"

同 ID 替换后："建议只修改登录页"
